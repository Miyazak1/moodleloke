# Agent 单一学习旅程与对话式教学干预架构决策

> 状态：Accepted / PR13A–PR13J implemented；学生旅程联动契约已确认
>
> 日期：2026-09-15
>
> 决策：学生面对的是一条持续演进的 CSCA 学习旅程，而不是一组彼此割裂的聊天会话；聊天负责解释、协同和教学干预，类型化工作区负责做题、讲解演示、真题与验证。
>
> 2026-09-17 补充：以学生真实使用旅程明确聊天与任务面板的联动契约、安静陪伴原则和产品验收口径。

## 1. 决策摘要

CSCAPilot Agent 的任务边界与通用 Agent 不同。它不承担多项目编码、开放式办公或任意主题问答，而是持续帮助同一位学生达到目标 CSCA 分数。因此，“新建聊天 + 最近聊天列表”不应成为产品主结构。

学生侧采用以下模型：

```text
一名学生
  -> 一条持续学习旅程
  -> 当前目标与实时学习状态
  -> 系统给出的下一项行动
  -> 做题 / 教学 / 验证
  -> 新证据与新判断
  -> 下一项行动
```

底层仍可保留 `conversationId`、阶段 Session、Run 和 Artifact，用于隔离上下文、恢复、审计、并发控制和成本管理；但这些工程对象不直接等同于学生看到的“多个聊天”。

## 2. 左侧栏：从会话列表改为学习旅程导航

### 2.1 推荐信息架构

左侧栏长期保持稳定，建议按学习任务而不是按聊天记录组织：

1. **下一步**：按学习设置中的默认方式展示系统推荐或自由练习入口，并恢复进行中的练习、教学与待验证事项；
2. **学习计划**：目标分数、考试日期、阶段目标和近期安排；
3. **学习历程**：按日期聚合的任务、教学干预、阶段总结和关键变化；
4. **错题与薄弱点**：可解释的知识点状态、典型错误和待巩固项；
5. **学习资料**：已用真题、教学动画、讲解、未来的视频与收藏内容；
6. **学习设置**：默认学习方式、自由练习默认值、学习目标、科目、语言、考试计划、可用时间和辅助偏好。

底部继续保留用户头像、名称、个人设置入口和返回 CSCAPilot 主站。当前学习状态可用一个克制的小型状态组件展示，但不能用虚构分数或未经校准的掌握度填充。

### 2.2 不再把“新建学习对话”作为主要动作

- 移除左栏顶部的“新建学习对话”；
- 学生开始一次学习时，进入同一旅程的“下一步”，而不是创建新会话；
- 必要时提供低频的“重新规划”动作，用于目标、考试日期或可用时间发生实质变化；
- 重新规划只生成新的计划版本，不清空历史证据、错题、掌握判断或教学记录；
- 学习历程以“日期 / 任务 / 阶段总结”聚合，避免出现大量标题相同的会话。

## 3. 中间聊天与类型化工作区的关系

聊天必须始终存在，但不需要把所有复杂交互塞进气泡。桌面端由可交换、可调整宽度的两个主面板组成：

- **对话面板**：解释系统判断、接收学生问题、呈现计划和主动教学提议；
- **任务面板**：完成练习、真题、教学动画、视频、手写分析、验证和报告。

学生可以交换两个面板的位置，也可以拖动分隔线调整宽度。被放在窄侧的面板必须进入紧凑布局，而不是简单裁切。对话不会因为打开做题或教学资产而消失。

“始终存在”是结构约束，不只是视觉偏好：

- 桌面端聊天消息流与 Composer 始终挂载，任务区打开、切换、交换位置或调整宽度都不能卸载聊天；
- 题目、讲解、动画、视频、手写详情和报告之间的切换，只改变任务区的 `workspaceMode`；
- 关闭任务区只结束当前工具的可见状态，不退出学习旅程、不清空聊天，也不丢失未提交任务状态；
- 移动端允许任务区覆盖显示，但关闭覆盖层后必须回到同一聊天位置、Composer 草稿和活动任务上下文；
- 模考如因考试政策限制聊天能力，必须以明确的专注状态表达，不能把聊天替换成另一套页面；退出或交卷后恢复原聊天。

### 3.1 对话面板负责什么

- 说明今天为什么学这个、依据是什么；
- 回答与当前题、当前知识点和当前计划有关的问题；
- 展示系统识别到的稳定误区和教学干预建议；
- 汇总一组题后的表现与下一步，而不是逐题刷屏；
- 承接学生主动发起的知识点学习、提示、手写过程分析；
- 在任务完成后解释证据变化，但不把“看过讲解”表述为“已经掌握”。

### 3.2 任务面板负责什么

- 逐题作答、计时、导航和正式提交；
- 打开交互动画、引导演示、例题、微课与未来的视频；
- 上传并查看手写过程，执行结构化分析；
- 完成教学后的独立验证；
- 展示本轮结果、错误归因和可追溯来源。

### 3.3 聊天与任务不能是两套孤立系统

对话消息和 Composer 至少应能引用以下活动上下文：

```text
journeyId
activePlanVersionId
activeTaskId / artifactId
workspaceMode
roundId
questionId
knowledgePointIds
answerAttemptId（如已正式提交）
teachingAssetId / interventionId（如适用）
```

前端只提交可见上下文标识，服务端必须重新鉴权并验证归属、状态和策略。模型不能仅根据前端文本猜测当前题，也不能绕过领域服务读取答案或写入掌握度。

### 3.4 双向联动与职责边界

任务区向聊天区发布经过校验的活动上下文：当前题、知识点、学生答案状态、用时、已发生辅助曝光和附件绑定。聊天区调用能力后，结果按类型处理：

- 简短知识回忆、渐进提示、错因追问和解释进入聊天时间线；
- 题干定位或条件强调可以驱动任务区高亮，但不得替学生写入答案；
- 动画、视频、交互微课、手写详情和结构化报告在任务区打开，聊天继续可用；
- “继续做题”恢复同一 Round 和题号，而不是新建会话或丢弃原任务；
- 所有辅助曝光写入统一证据链，独立完成与获得帮助后的完成不能具有相同证据权重。

因此，聊天区是学习协调与工具调用面，任务区是当前活动的执行面；二者共享一个 Session/Artifact 上下文，但不能相互替代。

### 3.5 学生心智模型：不是使用两个面板，而是在完成一次学习

学生不需要理解“聊天区”“任务区”“Artifact”或内部会话。学生进入产品时只有六类稳定意图：

1. 今天该学什么；
2. 现在开始做题；
3. 这题为什么错；
4. 卡住了，需要不同层级的帮助；
5. 我学得怎么样；
6. 我想自由练一会儿。

界面分区是系统组织能力的方式，不是学生需要管理的对象。默认路径中，学生不应先创建会话、选择工具或描述系统已经知道的当前题。常规学习动作优先通过明确按钮完成；只有追问、例外、临时改变意图和开放表达进入自然语言。

产品对学生只建立一个心智模型：

```text
Agent 告诉我下一步
  -> 我在任务面板完成学习
  -> 卡住时随时叫 Agent
  -> Agent 理解我正在做的题
  -> 完成后告诉我学到了什么、接下来做什么
```

聊天区只有同时满足以下条件才有独立产品价值：能够驱动或调整任务、能够感知当前题和作答阶段、能够承接分级辅助与教学、能够解释系统决策和证据限制。若聊天只是另一个通用问答框，或要求学生重复描述右侧正在发生的事情，则应视为联动未完成，而不是通过增加欢迎语或聊天功能补救。

### 3.6 六状态学生旅程

| 状态 | 学生看到什么 | 聊天职责 | 任务面板职责 | 主操作 |
|---|---|---|---|---|
| 进入 Agent | 一个有依据的下一步，而不是空白聊天 | 简短说明推荐原因并提供备选 | 默认关闭或展示待开始任务摘要 | 开始任务 / 自由练习 |
| 任务执行 | 当前题、进度、提交与计时 | 安静陪伴，显示当前任务上下文，不主动刷屏 | 专注完成题目或真题 | 作答 / 提交 |
| 主动求助 | 当前题不消失 | 接收自然语言或快捷求助，返回知识回忆、渐进提示与追问 | 可高亮题干、接收手写上传，但不复制整套聊天 | 提示 / 检查过程 / 讲解 |
| 稳定误区 | 在自然边界收到有依据的建议 | 插入非阻塞教学卡，允许现在、稍后或跳过 | 学生接受后打开动画、微课或视频，保留原题状态 | 现在学习 / 稍后提醒 |
| 任务完成 | 本轮真实结果和一个明确下一步 | 聚合解释表现、辅助曝光和证据限制 | 展示本轮报告，需要时进入独立验证 | 继续巩固 / 换知识点 / 结束 |
| 再次进入 | 上次未完成事项或最新下一步 | 解释恢复了什么，不要求寻找旧聊天 | 恢复原 Round、题号、教学或验证状态 | 继续上次学习 |

进入 Agent 时系统应主动读取已有目标、证据、进行中任务和题源，生成首选行动；“我今天学什么”仍可作为自然语言入口，但不应成为学生每次启动学习的必经步骤。

### 3.7 安静陪伴与 80/20 交互原则

- 至少 80% 的常规路径应能通过任务卡和明确按钮完成，包括开始、继续、暂停、求助、接受教学、完成与进入下一步；
- 聊天承担无法被固定按钮完整表达的 20%：追问原因、换一种讲法、临时改目标、描述困惑、上传过程和要求不同帮助层级；
- 任务执行期间，Agent 不为展示存在感而持续发消息。原始选项变化、计时和每次点击只进入领域事件，不进入聊天；
- 当前题提交、mini-set 完成、稳定误区形成、教学完成和验证结算是允许主动发言的自然边界；
- 学生发出“这题”“刚才为什么错”“检查一下”时，系统必须优先解析活动上下文，不得要求重复提供题号或重新上传已经绑定的材料；
- 最新聊天消息默认锚定在 Composer 上方；任务区打开、交换位置、动态卡片展开和刷新恢复都不能把学生留在过期消息位置。

### 3.8 双向联动事件契约

前端可以用本地 UI 事件维持即时体验，但跨刷新、跨端和学习证据所需状态必须来自服务端。建议将联动收口为以下语义事件：

| 事件 | 来源 | 聊天区反应 | 任务面板反应 | 是否进入正式证据 |
|---|---|---|---|---|
| `task.started` | 任务面板 | 显示一次开始节点，随后进入安静状态 | 打开并定位当前任务 | 是，记录任务开始 |
| `question.focused` | 任务面板 | 更新 Composer 当前题上下文，不新增消息 | 定位题目 | 否，仅活动上下文 |
| `answer.submitted` | 领域服务 | 只在有解释价值时产生反馈 | 锁定或进入下一题 | 是 |
| `assistance.requested` | 聊天或题目快捷入口 | 展示处理中与分级反馈 | 保持当前题，可执行高亮或上传 | 是，记录辅助曝光 |
| `misconception.detected` | 学习智能 | 在自然边界生成教学建议 | 不自动覆盖当前题 | 是，记录判断来源 |
| `teaching.accepted` | 聊天教学卡 | 保留建议与追问入口 | 打开对应教学资产 | 是，记录接受与曝光，不代表掌握 |
| `teaching.completed` | 任务面板 | 说明完成并提供独立验证 | 关闭或切换到验证 | 是，不直接提高掌握度 |
| `task.completed` | 领域服务 | 生成聚合总结和一个下一行动 | 展示报告或收起任务 | 是 |
| `workspace.resumed` | Journey 读模型 | 说明已恢复的活动 | 恢复同一对象与位置 | 否，不重复写入学习事件 |

每个跨区命令至少携带 `journeyId`、`conversationId`、`artifactId/taskId`、`workspaceMode` 和与场景对应的题目或教学标识；服务端重新校验归属和当前状态。聊天不能直接修改答案、掌握度或正式任务状态，任务面板也不能自行生成学习决策。

## 4. Composer：当前学习任务的统一辅助入口

Composer 不是独立的泛聊天输入框，而是与当前任务自动绑定的学习入口。

- 空闲时：询问计划、知识点或下一步；
- 做题时：自动绑定当前题，提供“给我一点提示”“解释题意”“检查手写过程”等快捷能力；
- 教学时：可追问当前演示步骤、概念和例题；
- 真题时：带入试卷、题号、页码与可信来源；
- 模考时：严格遵守考试模式的辅助限制；
- 报告时：解释错因、证据变化与后续安排。

附件入口支持图片和文档。拍照手写答案时，应把附件、当前题和本次尝试绑定到同一个分析请求。OCR / 多模态输出属于辅助证据，不直接等同于正式作答或掌握事实。

做题区只保留轻量“向 Agent 求助”入口与必要的考试状态，不在题卡底部复制完整知识讲解、提示历史或手写分析面板。学生主动调用和系统主动教学都进入聊天流；需要复杂交互时，再由聊天中的可行动卡打开任务区工具。

## 5. 主动教学不是弹窗，而是对话中的可行动干预

### 5.1 触发条件

系统不能因为一次错误立即打断学生。只有在实时证据形成稳定信号时才提出教学干预，例如：

- 同一知识点连续或高频出错；
- 错误模式跨题重复，指向同一概念误区；
- 多次提示后仍无法独立完成；
- 先前教学后的验证仍失败；
- 当前计划明确安排了前置知识补齐。

触发判断必须包含最小样本、置信度、冷却期、近期是否已教学、资产可用性和当前任务是否允许被打断。

### 5.2 呈现与时机

“自动弹出”定义为 Agent 主动向聊天流插入一张教学干预卡，而不是阻塞页面的 Modal。卡片至少包含：

- 发现了什么具体困难；
- 使用了哪些真实学习证据；
- 建议学习哪个知识点、预计多久；
- 将使用何种教学形式；
- `现在学习`、`稍后提醒`、`暂时跳过`。

干预应在当前题提交后或一个 mini-set 结束的自然边界出现，不在学生读题、输入或计时作答中突然覆盖界面。紧急的考试安全提示除外。

### 5.3 教学资产形态

教学资产是可执行内容，不只是题目下方的一段文字：

| 类型 | 用途 |
|---|---|
| `interactive_visualizer` | 用可操作图形展示变量、关系和变化 |
| `guided_demo` | 分步骤演示推理或解题过程 |
| `worked_example` | 完整例题与关键决策点 |
| `contrast_example` | 对比易混概念或正确/错误路径 |
| `micro_lesson` | 短篇结构化讲解 |
| `video` | 后续接入的讲解视频，保留字幕与章节 |
| `verification` | 教学后的独立短测，不向学生泄露答案 |

学生点击“现在学习”后，资产在任务面板打开，聊天仍保留并可追问。资产完成只记录曝光、互动和完成情况；随后必须通过独立验证产生新的学习证据，才能更新判断和下一计划。

## 6. 学生主动调用知识帮助

主动教学与学生主动学习共用同一套教学资产和策略，但入口不同：

- 在 Composer 中直接提问或请求讲解；
- 在当前题快捷能力中选择“回忆知识点”或“讲解这个概念”；
- 从“错题与薄弱点”或知识地图打开某个知识点；
- 从学习历程重新查看之前的教学资产。

主动打开不应默认修改学习计划。系统记录使用过程，只有后续正式作答或验证才能影响掌握判断。

## 7. 对话消息与学习事件

为避免聊天刷屏，前端消息建议区分以下展示类型：

- `assistant_message`：常规解释与回答；
- `plan_decision`：下一项任务及其依据；
- `task_checkpoint`：开始、暂停、完成等关键节点；
- `assistance_response`：提示、手写过程反馈、题意解释；
- `intervention_offer`：主动教学干预卡；
- `learning_summary`：一组题或一个阶段后的聚合总结；
- `next_action`：根据新证据生成的后续行动。

并非每个领域事件都要成为聊天消息。原始作答、计时、曝光和恢复事件进入审计与学习证据层；只有对学生有解释价值的事件才进入对话流。

## 8. 完整闭环

```text
学生实时作答
  -> 领域服务记录正式学习事件
  -> 学习智能更新状态并识别稳定误区
  -> 决策层在自然边界生成干预建议
  -> 聊天插入教学干预卡
  -> 学生接受后在任务面板完成教学资产
  -> 进行独立短验证
  -> 新证据更新学习判断
  -> Agent 解释变化并安排下一项行动
```

## 9. 安全、诚实与体验约束

- 不用单次错误制造“你不会”的确定性结论；
- 不在聊天中泄露当前未提交题目的答案；
- 不把教学曝光、视频播放完成或动画点击当作掌握；
- 不为提高互动率而频繁打断，必须有冷却和每日上限；
- “稍后提醒”和“跳过”是有效选择，不进行羞辱性提示；
- 计划、题目、讲解和真题引用必须保持事实来源与版本；
- 会话分段、摘要和上下文压缩不得丢失正式学习证据；
- 关键决定应可解释、可审计、可恢复。

## 11. 实施顺序

1. 左栏改为学习旅程导航，隐藏面向学生的多会话创建与重复列表；
2. 建立单一旅程首页和按日期聚合的学习历程；
3. Composer 自动绑定活动任务、题目和知识点上下文；
4. 将提示、手写检查和知识点帮助的主要反馈接入聊天流；
5. 把现有主动干预契约渲染为聊天教学卡，并在任务面板打开教学资产；
6. 接通教学完成、独立验证、状态更新和下一行动；
7. 完成刷新恢复、窄栏、移动端、键盘操作和真实浏览器黄金路径。

## 12. 验收标准

- 学生不需要创建或管理多个同名会话，也能连续完成跨日学习；
- 左栏能回答“今天做什么、计划是什么、我学过什么、哪里薄弱、资料在哪里”；
- 打开练习或教学时，聊天始终存在且知道当前上下文；
- 学生可以交换并调整聊天与任务面板，窄栏内容不溢出；
- 重复错误达到策略门槛后，在自然边界出现有依据的教学卡；
- 教学资产在任务面板执行，聊天可同步追问；
- 教学完成不直接提高掌握度，独立验证后才产生正式学习证据；
- 刷新或断线后能恢复当前旅程、任务、干预和验证状态。
- 学生首次进入即可看到可执行的下一步，不必先发送“今天学什么”或创建会话；
- 学生在当前题说“提示一下”“为什么错”“检查过程”时，无需重新说明题号；
- 做题期间聊天保持可用但不因普通选项、计时和导航事件刷屏；
- 任务、教学、验证和报告的关键事件能双向同步，且辅助曝光与独立作答具有不同证据权重；
- 长会话恢复、新消息到达和动态教学卡展开后，最新消息仍位于 Composer 上方；
- 学生可拒绝或延后主动教学，不丢失当前答案、题号和任务进度；
- 一轮结束后界面只突出一个推荐下一步，并允许继续、换方向或结束。

## 13. PR13A 首步实施记录

PR13A 已把 Web Agent 左栏从“新建对话 + 最近对话”改为学习旅程导航。学生不再手动创建会话；首次发送内容时由 Runtime 自动建立内部会话，后续内部会话只在“学习历程”中作为带日期的学习阶段展示。

本步同时保存当前旅程栏目，并继续复用任务面板宽度、面板顺序和 URL 工作区恢复状态。错题、资料与个人设置在迁移期使用已有真实页面作为回退入口；它们仍需在后续阶段迁入 Agent 原生工作区，因此 PR13A 不代表整份 ADR 已全部完成。

PR13B 已将“学习计划”和“学习历程”接入 Agent 原生只读数据视图：计划读取已持久化的 `learning_plan` Artifact，展示任务、科目、时长、题量和事实来源；历程按内部会话加载真实消息与 Artifact 计数，并允许恢复对应阶段。两者都保留中间聊天，不再跳转旧学习页面或把内部会话重新包装成通用聊天列表。

PR13C 已建立练习工作区与对话区之间的当前题上下文桥：Composer 展示并提交经服务端重新校验的 `adaptive_round + questionId` 上下文；A1 知识回忆、A2 渐进提示和 A3 手写过程检查从题下大面板迁入聊天流；练习区只保留轻量求助提示。辅助仍调用既有 Learning Assistance 与附件分析领域接口，不改变答案泄露门、额度、曝光或掌握度语义。刷新时按当前 Round 恢复全部题目的已记录 A1/A2 辅助，并从同一 Agent conversation 恢复手写分析。

PR13D 已完成主动教学资产的 Agent 原生合流：练习报告产生的教学建议回到聊天流展示，不再在题目或报告内部展开微课；学生接受建议后，已审核的交互动画在可拖拽、可交换的任务面板中运行，聊天保持可见。进行中的讲解通过 `agentTeachingDeliveryId` 写入 URL，刷新后由服务端返回的活动 Delivery 恢复。完成资产内部即时检查后，系统只记录教学完成与曝光，不直接修改掌握度，并在聊天中给出独立新题验证入口；验证仍复用既有的未曝光题选择、提交、结算和学习证据投影链路。

PR13D 没有新增另一套教学判断或题目生成逻辑。主动触发继续由 Learning Intelligence 的最小样本、重复错误、冷却、正式模考抑制和已审核资产可用性策略决定；Web 只负责把既有 Delivery、Teaching Asset 与 Verification 按“聊天提议—任务面板学习—聊天验证”的产品模型编排起来。
# 实施状态

PR13D 已完成“聊天内建议、任务面板承载教学、完成后独立验证”的产品闭环；PR13E 已增加可重复的真实浏览器演示场景和自动彩排。具体运行方式见 `81-AGENT-TEACHING-BROWSER-DEMO.md`。

PR13F 将真实浏览器验收延伸到验证题作答、服务端结算和返回 Agent：聊天必须披露当前阶段的正确题数，并明确即时通过不等于稳定掌握；未通过或证据不完整时不得提高掌握结论。即时通过只会安排到期保持验证，最终仍需完成保持与迁移阶段才能声明稳定掌握。

PR13G 将上述链路扩展为可重复验收的三阶段稳定掌握闭环：隔离演示题源提供不少于九道未曝光题，并用可审计任务结构签名区分直接方向判断、顶点参数读取、多步图像变换和情境迁移；即时、保持和迁移各自独立结算，任一阶段失败或证据不完整都会终止稳定掌握声明。保持验证仍按生产策略延迟开放，本地彩排仅通过受本地数据库和隔离场景双重约束的推进脚本模拟到期。Agent 会按当前阶段准确说明下一项验证，只有三阶段全部通过才显示稳定掌握。

PR13H 将稳定掌握闭环正式接入 Agent 原生学习计划与学习历程。每次由验证返回 Agent 生成的新 `learning_plan` Artifact 都保存结构化 `decisionImpact`，区分“后续验证已安排、稳定掌握、继续巩固、证据不足、阶段已记录”，同时保存当前阶段、已完成与已通过阶段数、下一到期时间和验证来源。学习计划展示该决策如何改变当前下一任务；学习历程不再只列内部会话，而是按真实 Artifact 版本展开方案变化时间线。下一任务仍由同一 `get_learning_prescription` 决策结果产生，前端不自行推断或排序。

PR13I 将左栏“错题与薄弱点”和“学习资料”从旧站跳转迁为 Agent 原生只读数据视图。后端 Journey Overview 直接复用 Learning Intelligence 的 `getSubjectMastery`、`getReviewQueue` 与已发布真题服务：薄弱点只展示 `user_csca_topic_mastery_v1` 投影和真实复习队列，资料只按个人目标科目返回已发布真题。前端不复制掌握判断、复习排序或题源审核逻辑；打开资料后进入 Agent 真题任务面板，聊天区继续存在并可绑定题目上下文。

PR13J 将“学习设置”迁入 Agent 原生可交换任务面板。面板只承载会改变学习决策的学习画像、版本化考试目标和长期学习时间，直接复用 `/api/v1/me/student-profile`、`/api/v1/me/agent-score-goal` 与 `/api/v1/me/agent-study-availability`；聊天始终保留，面板继续支持拖动宽度和交换位置。底部头像卡是唯一“个人设置”入口，直达账号中心设置分区；账号安全、机构邀请码与额度治理仍留在账号中心，避免把非学习决策能力复制进 Agent。设置保存只影响后续 Prescription，不回写或改写既有学习证据。

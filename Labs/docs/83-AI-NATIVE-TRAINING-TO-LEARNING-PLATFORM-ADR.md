# 从 AI 原生做题训练到学习平台的演进架构决策

> 状态：Accepted
>
> 日期：2026-09-17
>
> 决策：CSCAPilot 以做题训练为当前产品切入点，以真实作答证据驱动学习辅助和教学闭环；当前不复制完整 Moodle，但必须通过统一活动、版本化内容、学习证据、组织边界和能力接口，为未来扩展到教师、课程、班级与机构教学保留稳定路径。

## 1. 背景与问题

CSCAPilot 当前最明确的用户价值是让学生获得可信题目、完成训练、得到与当前题紧密相关的辅助，并根据真实表现决定下一步。产品正在把知识点讲解、交互动画、视频、手写分析和主动教学干预逐步接入这一过程。

长期上，平台可能覆盖 Moodle 所承担的课程、教学、教师、班级和机构学习管理能力。但如果现在直接建设完整 LMS，会同时引入大量尚未验证的管理场景，稀释题源、作答体验、辅助质量和学习效果这些当前核心问题；如果只按单一练习页面快速堆叠，又会使未来加入教学与机构能力时被迫重建领域模型。

因此需要明确：当前聚焦什么、未来如何演进、哪些边界必须现在建立、哪些能力应明确延后。

## 2. 外部参照与判断

Moodle 不是单纯的课程页面，而是由用户与上下文权限、选课、课程活动、题库与作答引擎、成绩、能力计划、内容仓库、报表、后台任务、移动端、隐私以及插件和外部服务共同组成的平台。其官方资料显示，Moodle 已覆盖成绩册、能力与学习计划、协作、移动离线、多语言、无障碍、报表和大规模插件生态：

- [Moodle LMS features](https://moodle.com/solutions/lms/features/)
- [Moodle plugin types](https://moodledev.io/docs/5.1/apis/plugintypes)
- [Moodle Question API](https://moodledev.io/docs/5.1/apis/subsystems/question)
- [Moodle External Services API](https://moodledev.io/docs/5.0/apis/subsystems/external)
- [Moodle Roles API](https://moodledev.io/docs/5.0/apis/subsystems/roles)
- [Moodle Enrolment API](https://moodledev.io/docs/5.0/apis/subsystems/enrol)

Moodle 也已经提供可切换供应商的 AI 子系统，因此“LMS 加聊天框”本身不能构成长期差异：[Moodle and AI](https://moodle.com/solutions/moodle-and-ai/)。

CSCAPilot 不应正面复制上述全部功能。它的差异化入口是学生实时学习过程：从真实作答取得证据，识别困难，提供适量帮助或教学，再通过独立任务验证学习结果。

## 3. 产品定位

### 3.1 当前定位

CSCAPilot 是一个以真实作答证据驱动的 AI 原生训练与教学产品。第一阶段首先解决：

1. 是否有足量、可信、适合当前学生的题目；
2. 学生能否顺畅开始、完成、暂停和恢复训练；
3. Agent 是否理解当前题、当前作答阶段和已经发生的帮助；
4. 提示、讲解、手写分析和教学资产是否真正帮助学生继续学习；
5. 作答是否形成可追溯证据，并驱动薄弱点、教学和下一任务。

### 3.2 长期定位

平台从学生真实学习过程向外扩展，逐步覆盖教学内容、教师工作流、课程、班级和机构能力，最终可以承载 Moodle 的核心使用场景，但不以复制 Moodle 的菜单、页面和课程中心模型为目标。

长期演进主线：

```text
做题训练
  -> 学习辅助
  -> 错因识别
  -> 教学干预
  -> 独立验证
  -> 持续学习计划
  -> 教师教学与内容发布
  -> 班级、课程与成绩
  -> 机构学习平台
```

传统 LMS 主要从“课程 -> 章节 -> 活动 -> 完成与成绩”组织系统。CSCAPilot 的运行时中心是：

```text
学生目标
  -> 能力与知识结构
  -> 当前证据
  -> 下一学习任务
  -> 训练 / 教学 / 验证
  -> 新证据
  -> 重新决策
```

课程未来仍然存在，但课程是教师组织、发布和治理学习内容的方式，不是学生学习决策的唯一中心。

## 4. 当前必须打通的学习闭环

```text
选题
  -> 作答
  -> 判定
  -> 错因与不确定性
  -> 分级辅助
  -> 必要时进入教学
  -> 独立验证
  -> 更新证据与下一步
```

教学能力应从训练过程自然生长，而不是先建设一套孤立的在线课程系统：

- 单次错误通常只产生适量反馈，不立即打断；
- 重复错误或稳定误区达到策略门槛后，Agent 在自然边界提出教学建议；
- 学生接受后，在任务工作区打开动画、引导演示、例题、微课或视频；
- 聊天区持续存在，学生可以围绕当前教学内容追问；
- 完成教学只记录曝光与互动，不等于掌握；
- 后续独立验证才产生新的能力证据。

## 5. 为未来扩展必须现在建立的架构边界

### 5.1 统一学习活动模型

练习、诊断、错题复习、真题、动画、视频和验证不应成为互不兼容的孤岛。建立统一的 `LearningActivity` 概念，并允许不同活动注册自己的运行时和工作区：

```text
LearningActivity
  - practice
  - diagnostic
  - review
  - past_paper
  - teaching_animation
  - guided_demo
  - worked_example
  - video
  - verification
  - assignment       # future
  - discussion       # future
```

所有活动共享最小生命周期：可见、开始、进行中、暂停、恢复、完成、取消；共享归属、版本、权限、进度、产出和事件契约。不同活动仍可拥有专用状态机，不能为了形式统一而抹平考试、教学和讨论的语义差异。

### 5.2 版本化内容与来源

题目、解析、教学动画、视频、例题和未来课程内容至少保留：

- 稳定内容标识与不可变版本标识；
- 作者、来源、语言、版权或使用授权；
- 科目、知识点、难度与适用条件；
- 草稿、审核、发布、下架状态；
- 创建者、审核者和发布时间；
- 组织归属与可见范围；
- 与历史作答、教学和验证结果的版本关联。

未来的课程编辑首先是对版本化内容和活动的编排，不另建一套内容事实源。

### 5.3 统一作答与学习证据

正式学习事实独立于具体页面：

```text
Attempt
  -> AnswerSubmission
  -> AssistanceExposure
  -> Evaluation
  -> LearningEvidence
  -> Mastery / Review / Plan Projections
```

正式证据采用只追加、可追溯语义；掌握度、薄弱点、复习队列和计划是可以按算法版本重建的投影。自由练习、教师作业、班级测验和课程活动未来都写入同一证据体系，但根据活动条件、辅助曝光和监考强度赋予不同证据权重。

### 5.4 组织与权限边界

当前可以主要服务个人用户，但核心资源必须允许表达平台、个人和组织归属，包括 `tenantId / organizationId`、所有者、发布者、可见范围和权限上下文。初期可使用默认平台租户，不为尚未存在的复杂院校层级提前建设 UI。

权限逐步从固定的 `admin/student` 角色迁移为角色与能力结合的判断，例如：

```text
question.attempt
content.view
content.author
content.review
activity.assign
submission.grade
learningEvidence.viewOwn
learningEvidence.viewStudent
```

当前只启用实际需要的能力，未来增加教师、教研员和机构管理员时扩展上下文绑定。

### 5.5 Agent 是控制层，不是事实源

Agent 通过稳定能力调度系统：

```text
create_activity
start_attempt
submit_answer
request_assistance
open_teaching_asset
complete_teaching
create_verification
get_learning_state
recommend_next_action
```

模型可以解释状态、提出计划和请求执行命令，但不能直接写入答案、成绩、掌握度、选课关系或正式学习证据。所有写操作必须经过领域服务、权限校验、输入校验、幂等控制和审计。

### 5.6 领域事件与扩展接口

跨模块协作使用稳定语义事件，例如 `activity.started`、`answer.submitted`、`assistance.exposed`、`teaching.completed`、`verification.completed` 和 `plan.revised`。事务内事实写入与事件发布使用 Outbox 等可靠交付机制；消费者必须幂等。

当前不承诺公共插件市场，但内部模块接口、版本化 API、事件名称和能力注册不能依赖具体页面。未来的 LTI、QTI、H5P、SCORM、SIS、Webhook 和 Moodle 迁移适配器建立在这些边界之上。

## 6. 推荐的物理架构

现阶段继续采用模块化单体，不因长期平台目标过早拆分微服务：

```text
Platform Core
├── Identity & Organization
├── Content Registry
├── Question Bank
├── Activity Runtime
├── Assessment & Attempts
├── Learning Evidence
├── Teaching Assets
├── Agent Orchestration
├── Learning Decision
└── Notifications & Background Jobs
```

要求模块拥有明确的数据所有权和应用服务边界，避免跨模块直接修改表。题目生成、模型调用、媒体处理、搜索或分析任务只有在安全边界、故障隔离或独立扩容确有需要时才拆成独立服务。

不要求整个业务使用事件溯源；正式学习证据使用只追加账本，业务当前状态仍可使用常规事务模型和可重建读模型。

## 7. 当前明确延后的能力

以下能力不是当前做题训练阶段的交付目标：

- 完整课程编辑器和课程模板市场；
- 教师批量排课、复杂班级管理和多层院校结构；
- 论坛、Wiki、博客和通用协作套件；
- 完整机构成绩册和复杂评分工作流；
- SCORM、LTI、QTI、H5P 的全量实现；
- 公共插件市场；
- 大型机构数据仓库和自助报表；
- 完整 Moodle 迁移工具；
- 为未来假设而提前拆分大量微服务。

延后不等于忽略：新增模型和接口不得把这些未来能力变成必须推翻现有训练内核才能实现的事项。

## 8. 分阶段演进

### 阶段 A：可信训练内核

- 稳定题源、作答、恢复、判定和报告；
- 统一辅助曝光与正式证据；
- 打通训练后的下一步决策；
- 使练习、诊断、复习和真题共享活动与证据契约。

### 阶段 B：训练中的教学闭环

- 教学资产注册、审核和发布；
- 主动与学生主动发起的教学；
- 动画、演示、例题、微课和视频工作区；
- 教学后独立验证与效果反馈。

### 阶段 C：教师与内容生产

- 教师/教研员角色和能力；
- 内容创作、审核、发布与版本管理；
- 布置活动、查看学生证据和人工覆盖；
- 最小班级、项目与成绩结果视图。

### 阶段 D：机构学习平台

- 组织、班级、选课、课程和日历通知；
- 机构权限、审计、隐私、备份和恢复；
- 标准接口、教务集成和迁移工具；
- 移动端离线与机构级运行保障。

### 阶段 E：开放生态

- 公共能力与活动 SDK；
- 第三方工具、内容和 Agent 能力接入；
- 教学资产与插件生态；
- 不同组织的模型、策略和数据驻留配置。

每个阶段只有在前一阶段的真实用户闭环稳定后才扩大范围。阶段 C 之前不以“功能数量接近 Moodle”作为成功标准。

## 9. 替代 Moodle 的市场策略

平台不应在早期要求学校整体迁移。进入机构市场时优先采用兼容路径：

1. 作为现有 LMS 的 AI 训练与教学层接入；
2. 通过 SSO/LTI 或受控连接同步用户、课程上下文、任务和结果；
3. 先替代学生日常训练体验和学习决策；
4. 在教师与机构能力成熟后，逐步承接更多系统记录职责；
5. 最后提供课程、题库、成绩和用户的迁移工具。

这使 CSCALite 可以先证明学习效果，而不把早期成败绑定到高风险的全量 LMS 替换。

## 10. 架构守则

后续设计和实现必须遵守：

1. 学习效果优先于功能覆盖率；
2. 课程可以扩展训练内核，不能成为另一套事实源；
3. 正式证据只追加、可追溯，投影必须带算法版本；
4. 教学曝光不等于掌握，必须由独立任务验证；
5. Agent 不直接修改高影响学习事实；
6. 内容、题目和活动必须版本化并保留来源；
7. 组织与权限边界进入领域模型，但复杂机构 UI 按需建设；
8. 先保持模块化单体，通过稳定契约保留拆分能力；
9. 公共标准和插件生态在核心领域稳定后建设；
10. 新功能必须说明它如何进入活动、证据、教学和下一步闭环。

## 12. 当前建设检查表

新增训练或教学能力时，至少回答：

- 它属于哪一种 `LearningActivity`，生命周期如何；
- 使用哪个内容和版本，来源是否可追溯；
- 产生哪些正式事件，哪些只属于 UI 状态；
- 是否使用了提示、示例或答案，证据独立性如何变化；
- 哪个领域服务有权写入结果；
- 如何恢复、重试和保持幂等；
- 当前个人用户如何使用，未来组织上下文如何表达；
- 它是否改变下一步决策，依据和解释是什么；
- 是否可以在不复制数据和规则的前提下被教师活动复用。

# Agent 双模式学习编排 ADR

> 状态：Accepted / 连续学习闭环与统一历程读模型已实现
> 适用范围：Web Agent、后续插件客户端、学习历程与实时学习决策

## 1. 决策

学生端同时提供两种学习入口，但只维护一套题源、辅助、作答证据、掌握投影与学习历程：

1. **智能推荐**：系统根据目标、考试日期、真实作答证据、到期复习项与已发布题源给出一个可解释的下一步。推荐不是强制课程表，学生可以忽略、推迟或切换模式。
2. **自由练习**：学生决定何时开始、练习科目和当前批次题量，可以随时停止；完成一批后可继续下一批。自由练习产生的正式作答证据继续影响系统推荐。

“今日任务”不再表达每日强制完成，产品统一改称“下一步”。进入 Agent 只展示当前默认方式对应的入口，不自动开始任务。默认方式在“学习设置”中维护，避免学生每次开始学习前都重复作模式决策。

## 2. 不变量

- 两种模式都只使用已发布、符合治理规则且对当前学生未失效的题源；
- 两种模式都复用自适应练习工作区、学习辅助阶梯、附件/手写检查和 Evidence Writer；
- 模式来源必须显式记录为 `system_recommended` 或 `student_initiated`，不得把学生主动选择伪装成系统处方；
- 自由练习不创建 `LearningPrescriptionOutcome(accepted)`，但正式作答仍形成学习证据并进入投影；
- 辅助曝光继续降低证据独立性，观看讲解不能直接提高掌握度；
- 自动出题系统不由学生请求或 Agent 前端直接调用。题源不足时返回短缺，不静默生成；
- 聊天始终保留，练习在可交换、可调整宽度的任务面板内执行。

## 3. 自由练习的“无限”语义

无限模式不是一次创建无限题目。服务端按小批次分配题目，首版每批允许 `1–10` 题，默认 `5` 题：

1. 学生选择科目和本批题量；
2. 服务端重新校验身份、题源与防复用规则；
3. 创建标准自适应 Session/Round；
4. 本批结算后学生选择继续或结束；
5. 继续时再创建下一批，保留同一学习旅程上下文；
6. 结束时形成阶段总结并触发学习决策重算。

这样可以随时停止，也避免预占大量题目、长事务和无边界上下文。

## 4. 学习计划与学生控制

学习计划保持“系统制定、学生协商”，不允许前端直接写知识点掌握度或重排证据。后续控制包括：

- 接受、推迟、跳过或更换推荐任务；
- 修改可用时间、固定安排、科目偏好和休息日；
- 用自然语言提出临时学习意图；
- 每次调整生成版本化计划，并保存原因和约束快照。

学习方式分为两层状态：

- `defaultLearningMode`：长期默认方式，在学习设置中维护；
- `sessionModeOverride`：只影响当前学习阶段的临时选择，不反向覆盖长期偏好。

默认方式、自由练习默认科目和默认批次通过 `GET /api/v1/me/agent-learning-settings` 读取，并通过 `POST /api/v1/me/agent-learning-preference` 版本化更新。服务端把偏好保存在学生档案元数据的 `agentLearningPreference` 命名空间；Web 的 localStorage 仅作为启动缓存和离线回退，插件必须读取服务端契约，不能读取浏览器本地状态。

## 5. 学习历程

学习历程不能只读取对话或 `learning_plan` Artifact。目标聚合源包括：

- 系统推荐与学生主动练习；
- 练习、真题和模考的开始、完成与结算；
- 作答证据、错因、知识点状态变化；
- 辅助曝光、教学干预与三阶段验证；
- 计划版本和学习设置变化。

对话是解释层，不是事实来源。

### 5.1 统一读模型（已实现）

服务端通过 `GET /api/v1/agent/journey/state` 返回唯一的学习历程读取契约。Web 和后续插件不得再逐个读取对话后自行拼装历程。

读模型聚合并保留来源引用：

- `AgentArtifact`：系统推荐练习、学生主动练习、模考及其启动上下文；
- `CscaAdaptiveRound` / `MockExamAttempt`：题量、作答数、正确数、结算状态；
- `AgentPastPaperAttempt`：真题进度和结果；
- `AgentToolCall`：学习辅助实际调用次数；
- `LearningInterventionDelivery`：教学干预与讲解；
- `LearningInterventionVerification`：讲解后的独立验证，即使它没有 Agent Artifact 也必须进入历程。

每个 `stage` 统一输出状态、时间、批次数、题量、正确率、辅助/教学次数、可恢复工作区以及 `artifactIds` / `domainEntityRefs`。这些引用是审计入口，前端展示值不能反向成为事实源。

### 5.2 当前学习恢复（已实现）

`activeWorkspace` 由服务端从仍可继续的阶段中按最后更新时间确定，支持以下工作区：

- 自适应练习与自由练习（作答或报告）；
- 模考（答题或报告）；
- 真题作答；
- 教学内容；
- 教学干预后的独立验证。

恢复规则：

1. 学生访问无工作区参数的 `/agent` 时，客户端读取 `activeWorkspace`，载入所属内部对话并恢复任务区；
2. 刷新、重新登录或另一设备进入均不依赖 localStorage 中保存的 URL；
3. URL 已显式指定历史对话或任务时，以用户显式上下文为准，不被自动恢复覆盖；
4. 任务面板恢复后聊天区仍常驻；URL 只承担可分享的界面定位，不是真实状态来源；
5. 多个未结束阶段并存时暂按 `updatedAt` 最新者恢复，其他阶段仍在学习历程中可见；后续如引入并发任务约束，应在写侧消除歧义，而不是让各客户端自行选择。

读模型是派生视图，不新增迁移，也不复制掌握度。它允许短暂读取失败：Agent 仍可进入聊天，但学习历程与恢复显示为暂不可用；不能用空白数据伪装为“没有学习记录”。

## 6. 第一纵切

第一纵切交付：

- 左栏“今日任务”改为“下一步”；
- 学习设置提供“智能推荐 / 自由练习”默认方式，以及自由练习默认科目和批次；
- 下一步视图直接呈现默认方式对应的入口，不再放置永久模式切换器；
- 自由练习支持三科与 `3/5/10` 题小批次；
- 服务端通过独立 `start_student_initiated_practice` 契约创建标准自适应轮次；
- 创建 `learning_task` Artifact，并标记 `source=student_initiated`；
- 结算兼容学生主动任务，但不伪造处方接受记录；
- 作答、辅助、证据投影和任务面板继续复用现有正式链路。

## 7. 后续阶段

已完成的第二纵切：

- 每次自由练习生成稳定的 `freePracticeJourneyId` 与递增 `batchIndex`；
- 本批结算后，Agent 报告提供“按当前设置继续 / 调整下一批 / 结束本次学习”；
- 继续通过 `POST /api/v1/agent/free-practice/:artifactId/continue` 创建新的标准自适应 Round，且保留同一学习旅程；
- 结束通过 `POST /api/v1/agent/free-practice/:artifactId/end` 形成阶段总结；
- 每批结算把真实题量、正确数和正确率写入聊天总结，学习历程按 journey 聚合批次数和总题量；
- Agent 管理的自由练习报告不再预创建旧科目页的通用下一轮，避免产生脱离 Artifact 的孤儿 Round；
- 组间教学仍沿用既有干预契约：自然边界提出教学卡，教学资产在任务区打开，聊天始终保留，掌握更新必须等待独立验证。

后续增强：

1. 支持知识点与难度选择，并继续执行题源与防复用校验；
2. 为系统推荐增加推迟、替换和约束协商；
3. 将薄弱点与教学资产直接接入自由练习入口；
4. 在写侧增加“同一学生只能有一个前台当前任务”的治理策略，并提供显式任务切换；
5. 为统一读模型增加游标分页和独立投影表（仅在真实数据量证明在线聚合成为瓶颈后实施）。

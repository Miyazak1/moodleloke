# Agent 多题区域理解闭环（PR7E）

## 目标

学生上传一张包含多道题的作业照片，或上传多页 PDF 时，系统不再把整份附件压成一条学习判断。一次附件分析可以拆成最多 20 个题目单元，每个单元独立保存、匹配可信题源，并形成独立、可确认、可拒绝和可撤销的学习证据候选。

本阶段仍然只调用外部多模态模型 API，不部署本地大模型，也不调用自动出题系统。

## 数据边界

`AgentAttachmentAnalysis` 是一次附件分析任务；`AgentAttachmentAnalysisItem` 是其中一道可辨认的题。每个题目单元保存：

- 阅读顺序、题号、科目、题干与学生答案；
- 对错判断、错误说明、指导和不确定性；
- 页码与引用；
- 可选的归一化区域坐标；
- 一对一的可信题源匹配和学习证据候选。

旧分析没有题目单元时继续走原来的分析级候选路径。数据库使用局部唯一索引保证每个旧分析只有一条旧候选，同时允许新分析拥有多条逐题候选。

## 坐标契约

区域坐标采用页面左上角为原点的 `[0,1]` 归一化坐标：`x`、`y`、`width`、`height`，并携带 `pageNumber` 和固定的 `coordinateSpace=normalized`。

服务端是最终门控者：

- 只有视觉输入允许保存区域坐标；原生文本提取只保存页码；
- 数值被限制在页面范围内，宽高被裁到剩余页面边界；
- 零面积、负面积、无法解析或边界不可靠的区域直接保存为 `null`；
- 没有可靠区域不阻断逐题分析，但前端明确显示“页码定位”，不会伪造框。

## 处理流程

1. 多模态分析按页面阅读顺序输出题目数组。
2. 服务端验证 Schema、限制最多 20 道题、收敛页码和坐标。
3. 分析结果与题目单元在同一事务写入，并生成一条可回放的助手消息。
4. 每个题目单元独立运行可信题源匹配；匹配阈值和答案键验证规则沿用 PR7D。
5. 每道题独立形成候选。学生的确认、拒绝和撤销只作用于该题，不影响同一图片中的其他题。
6. 仅经学生确认的候选才写入学习证据；写入后继续使用既有投影、决策重算和撤销重放链路。

## 接口与兼容

既有单数接口 `GET /api/v1/agent/attachment-analyses/:analysisId/evidence-candidate` 保留原返回形状，并返回第一条候选以兼容旧客户端；全部候选可通过对话候选列表接口和助手消息取得。助手消息新增 `attachmentAnalysisItems` 和 `evidenceCandidates`；只有一条候选时仍附带旧字段 `evidenceCandidate`，使旧单题前端保持可用。

开关为 `CSCA_AGENT_MULTI_QUESTION_ANALYSIS_ENABLED`。本地一键启动脚本默认开启；生产环境应先灰度开启，并观察拆题数量、无坐标率、可信匹配率和学生拒绝率。

## 验证

- Prisma 迁移与 Schema 校验；
- 视觉坐标裁剪、非法区域丢弃、原生文本不保存区域；
- 单附件两道题分别持久化、匹配和生成候选；
- 逐题确认/拒绝/撤销与旧单题路径回归；
- 后端、前端构建以及学习证据投影、决策回归。

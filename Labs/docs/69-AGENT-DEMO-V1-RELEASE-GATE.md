## 2. 统一命令

先通过项目根目录的一键脚本启动现有网站、数据库和 Agent：

```bat
start-cscalite-dev.bat
```

只查看门禁计划，不调用模型：

```powershell
node scripts/agent-demo-release-gate.cjs
```

执行正式 5 轮真实门禁：

```powershell
node scripts/agent-demo-release-gate.cjs --execute --repetitions=5
```

门禁会在 `.local/agent-demo-release/` 写入 JSON 和 Markdown 报告；该目录只保存本机运行证据，不提交凭据或访问 token。

## 3. 门禁设计

每条黄金路径从确定性演示基线开始，避免前一条路径的题源曝光、练习状态或会话数据污染下一条路径：

```text
preflight
-> reset G1 -> G1 domain -> G1 browser
-> reset G2 -> G2 attachment
-> reset G3 -> G3 handwriting
-> 重复 5 轮
-> 汇总运行、分析、Provider、token、成本与延迟
```

认证只进行一次，后续子进程复用同一短期访问 token。这样既保留真实登录检查，又不会因为连续彩排触发正常的登录防刷限制。token 只通过子进程环境传递，不写入报告。

门禁 fail-fast：任何阶段、Agent Run、附件分析或 Provider 调用失败都会生成失败报告并返回非零退出码。

## 5. 彩排发现并关闭的问题

### 5.1 视觉模型返回 `subject=unknown`

题干与答案已正确识别时，模型仍可能无法稳定输出学科。可信题源匹配器升级为 v2：当题干对受治理题库形成高置信、唯一匹配时，可由匹配题源反向确定学科；相似度阈值、winner margin 和答案键验证仍全部保留，不能仅凭模型文本写入学习事实。

### 5.2 视觉 JSON 消耗完输出预算

结构化附件解析明确使用 `thinking=disabled`，避免把输出预算耗在内部推理而没有最终 JSON；本地启动上限同步为 8,000 tokens，并保留 Gateway 的结构化失败识别和重试能力。

### 5.3 分析摘要没有稳定展示题目

聊天界面现在直接展示服务器保存的 `attachmentAnalysisItems`：题号、抽取题干、学生答案与判定状态。学生不再依赖模型自由摘要来判断系统分析的是哪道题。

### 5.4 连续登录触发 429

统一门禁只登录一次并复用短期 token，不放宽生产认证限流。

### 5.5 路径之间相互消耗题源

G1、G2、G3 分别执行确定性 reset。重置是测试/演示隔离，不改变线上学生的真实连续学习语义。

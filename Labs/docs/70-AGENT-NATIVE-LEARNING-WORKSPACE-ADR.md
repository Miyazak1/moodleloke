# Agent 原生学习工作区架构决策

> 状态：Accepted v1.0
>
> 日期：2026-09-15
>
> 决策：Agent 是学生侧唯一主学习界面；聊天负责协调，练习、讲解、真题和模考以类型化工作区在 Agent 内完成。

> 交互补充：学生侧不以多个聊天会话组织学习。左栏、持续对话、主动教学卡和任务工作区的完整关系，见 [80-AGENT-LEARNING-JOURNEY-AND-CONVERSATIONAL-TEACHING-ADR.md](./80-AGENT-LEARNING-JOURNEY-AND-CONVERSATIONAL-TEACHING-ADR.md)。

## 1. 为什么调整

现有闭环是“Agent 推荐 → 跳转科目训练页 → 完成后返回 Agent”。它证明了领域能力和学习证据闭环，但把 Agent 降成了入口导航，也迫使学生理解科目训练、模拟题、错题等产品结构。最终产品应由系统依据目标和实时学习状态安排任务，学生只需在一个连续上下文里学习。

“一切在 Agent 内完成”不等于“一切都用聊天气泡”。对话是协调层，复杂任务使用适合其目的的交互面：

| 模式 | Agent 内呈现 | 边界 |
|---|---|---|
| `conversation` | 对话、推荐、事实依据、附件 | 不承载长表单和整套答题 |
| `practice` | 逐题作答、计时、导航和提交 | 辅助由常驻聊天区发起与反馈，继续调用现有练习领域 API |
| `lesson` | 知识卡、交互动画，未来可加入视频 | 完成讲解不直接提升掌握度 |
| `past_paper` | PDF/题目工作区、引用与辅助 | 保留来源、版本和页码 |
| `mock_exam` | Agent 路由内的沉浸式专注模式 | 计时中按考试政策限制辅助 |
| `report` | 本轮结果、错因、证据变化、下一步 | 结果回到原对话，不跳站外页面 |

## 2. 架构边界

```text
Agent Shell
  ├─ Conversation coordinator
  ├─ Typed Learning Workspace
  └─ Contextual Composer
          ↓
Agent Runtime / Capability Facade
          ↓
现有练习、模考、真题、教学资产、附件、学习证据领域服务
```

- 不复制出题、判题、计时、证据投影或额度逻辑；Agent 工作区只是这些领域能力的新学生端呈现。
- 不通过 iframe 嵌旧页面；复用 React 交互组件和稳定 API。
- 自动出题仍经独立供给契约和质量门，不成为 Agent 内同步调用的私有实现。
- 聊天区是常驻学习协调面，普通练习、讲解、动画、视频、手写分析和报告都不能替换或关闭聊天；它们只切换类型化任务区的内容。模考可按正式考试政策进入受约束的专注状态，但退出后必须恢复同一聊天与学习旅程。
- Composer 随工作区变化：练习时提供知识回忆、下一步提示、手写检查；模考时只开放政策允许的操作。

## 3. 状态、恢复与路由

活动任务至少绑定 `conversationId + artifactId + roundId + workspaceMode`。刷新后应恢复当前题、答案、用时和工作区，而不是回到旧科目首页。任务完成后：

1. 正式提交领域对象；
2. 生成不可变学习事件并更新投影；
3. 结算 Agent Artifact；
4. 在同一 Agent 内显示报告；
5. 用户确认继续后，让 Runtime 基于新证据生成下一步。

浏览器返回、主动关闭和断线恢复不得隐式提交或丢弃答案。放弃任务必须使用现有幂等放弃语义。

## 4. 迁移顺序

1. 普通练习：推荐、作答、辅助、手写检查、提交、报告、下一步全部内嵌；
2. 教学插入与独立验证统一进入同一工作区；
3. 真题阅读/作答进入 Agent；
4. 模考进入 Agent 专注模式；
5. 达到功能、恢复、移动端和无障碍等价后，从学生导航移除旧页面。

旧路由迁移期只作回退与内部运营入口。领域服务、历史数据和后台管理不随旧学生页面下线而删除。

## 5. 发布门

- 从推荐开始到下一方案生成，URL 不离开 Agent 主界面；
- 刷新可恢复活动任务，重复点击不重复建 Round；
- 普通练习的作答、辅助、手写分析、提交和报告能力与旧流程等价；
- 学习事实只来自正式提交事件，讲解曝光不冒充掌握；
- 模考辅助政策可审计，计时状态不可由聊天绕过；
- 旧页面下线前完成真实浏览器黄金路径、移动端、键盘操作和回滚演练。

## 6. 本次落地

PR12N 首步把现有 `AdaptiveRoundView` 与 `AdaptiveRoundReportView` 作为类型化工作区复用到 Agent Shell。`start-practice` 返回的 `roundId` 不再直接导航到科目训练页；练习与报告在 Agent 内切换，旧路由暂时保留为未迁移能力的回退。

PR12N 第二步将讲解后的即时、延迟保持和跨结构迁移验证接入同一工作区。验证仍使用既有独立题源、禁止辅助和幂等结算政策，只改变学生端呈现位置；刷新时通过 `agentInterventionVerificationId` 恢复验证上下文。

PR12N 第三步把 `search_past_papers` 的结果从纯文本链接升级为结构化、来源受控的真题卡片。学生可在 Agent 内切换原卷/答案/解析 PDF、阅读和下载，并把当前试卷及文件身份带回 Composer；公共真题文件不复制进 Agent 存储，仍由 Past Paper 服务负责发布状态和下载审计。

PR12N 第四步通过 `PastPaper.sourceDocumentId` 把公开资料显式绑定到既有可信源卷。Agent 工作区读取服务端题号/页码索引，Composer 只提交题目定位上下文，Runtime 重新验证绑定和使用策略后返回结构化题目与引用；无绑定或无已核验解析时禁止猜测。实现细节见 [71-AGENT-PAST-PAPER-CITATION-IMPLEMENTATION.md](./71-AGENT-PAST-PAPER-CITATION-IMPLEMENTATION.md)。

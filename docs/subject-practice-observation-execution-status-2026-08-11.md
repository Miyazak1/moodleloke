## Scope

This note records the current state of the backend-owned math observation path. It is a status note, not a new architecture source of truth. The architecture source remains:

## Implemented

- Backend-owned `subject_practice_observation` tasks execute through the singleton backend gateway rather than standalone provider code.
- Observation jobs carry `workClass=observation` and `observationTaskId`.
- Observation task/job idempotency, owner/token fencing, heartbeat, and cancellation boundaries are implemented.
- Observation-generated candidates do not count as ordinary production completions and do not trigger repair/regenerate chains beyond the unique observation job.
- Scheduler hint/adherence evidence is persisted to generated question metadata with `subject-practice-observation-adherence-v1`.
- `SUBJECT_PRACTICE_OBSERVATION_ONLY_MODE` defaults off and can isolate a temporary validation backend from ordinary subject-practice production queue, production runner, and predictive runner startup.
- Preflight reports `ready_after_observation_only_backend_start` until `observationOnlyMode=true` is visible.
- CLI apply refuses a non-observation-only backend by default and requires `--allow-shared-production-backend` for an explicit shared-backend override.
